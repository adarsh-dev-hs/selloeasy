The API is a Fastify 5 application. All business endpoints live under **`/api/v1`**, request and response bodies
are JSON, and every route is described by Zod schemas that also generate the OpenAPI document.

## Browse the OpenAPI spec

| What         | URL (local)                                                                              |
| ------------ | ---------------------------------------------------------------------------------------- |
| Swagger UI   | http://localhost:4000/api/docs, or through the web app at http://localhost:3000/api/docs |
| OpenAPI JSON | http://localhost:4000/api/docs/json (also `/api/docs/yaml`)                              |

The spec is generated at runtime by `@fastify/swagger` with `jsonSchemaTransform` from
`fastify-type-provider-zod`, so it always matches the deployed code. Endpoints are grouped by tags: `auth`,
`platform`, `platform-data`, `org`, `knowledge`, `icps`, `signals`, `pipeline`, `leads`, `crm`, `outreach`,
`dashboards`, `audit` and `ops`. There were **98** operations in v0.1.0; the platform data source added **27** more
(`platform-data` tag).

```bash
# list every operation from the live spec
curl -s http://localhost:4000/api/docs/json | jq -r '.paths | to_entries[] | .key as $p | .value | keys[] | "\(ascii_upcase) \($p)"'
```

## Authentication

Sessions are cookie-based:

| Cookie  | Contents                     | Path           | Lifetime                     |
| ------- | ---------------------------- | -------------- | ---------------------------- |
| `se_at` | Access JWT (`sub` = user id) | `/`            | `ACCESS_TOKEN_TTL` (15 min)  |
| `se_rt` | Opaque refresh token         | `/api/v1/auth` | `REFRESH_TOKEN_TTL` (7 days) |

Both are `HttpOnly`, `SameSite=Lax`, and `Secure` when `COOKIE_SECURE=true`. The OpenAPI document declares the
`cookieAuth` scheme (`se_at`). Non-browser clients can send `Authorization: Bearer <access JWT>` instead.

```bash
# log in and keep cookies
curl -c jar.txt -H 'content-type: application/json' \
  -d '{"email":"admin@roadgrip.local","password":"Password@123"}' \
  http://localhost:4000/api/v1/auth/login

# call an endpoint with the session
curl -b jar.txt 'http://localhost:4000/api/v1/leads?page=1&pageSize=6&band=HOT'

# rotate the session when the access token expires (401)
curl -b jar.txt -c jar.txt -X POST http://localhost:4000/api/v1/auth/refresh
```

A `401` means the access token is missing or expired. Call `POST /auth/refresh` once and retry, as the web client
does. See [Security](/docs/architecture/security#authentication) for rotation and reuse detection.

## Errors (RFC 7807)

All errors use `Content-Type: application/problem+json`:

```json
{
  "type": "about:blank",
  "title": "Lead not found",
  "status": 404,
  "code": "not_found",
  "instance": "/api/v1/leads/0199…",
  "requestId": "6f1c…"
}
```

Validation errors add a field list:

```json
{
  "title": "Validation failed",
  "status": 400,
  "code": "validation_error",
  "detail": "The request does not match the expected schema.",
  "errors": [{ "path": "lostReason", "message": "lostReason is required when moving a lead to LOST" }],
  "instance": "/api/v1/leads/…",
  "requestId": "…"
}
```

| Status | `code`                                  | Typical cause                                                                                                                                                                |
| ------ | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400    | `validation_error`, `bad_request`       | Schema violation, business rule (e.g. activation prerequisites, last admin)                                                                                                  |
| 401    | `unauthorized`                          | No or expired session                                                                                                                                                        |
| 403    | `forbidden`                             | Missing permission, Super Admin on a tenant route, SDR on someone else's lead, locked account                                                                                |
| 404    | `not_found`, `route_not_found`          | Missing **or cross-tenant** resource                                                                                                                                         |
| 409    | `conflict`                              | Optimistic-lock conflict (`details.currentVersion`), lead already claimed, run already in progress (`details.runId`), duplicate email, batch or connector in the wrong state |
| 422    | `unprocessable`                         | Import file rejected at the file layer (`details.batch`), commit refused by the invalid-ratio guard or with nothing to commit                                                |
| 429    | (rate limit)                            | Too many requests                                                                                                                                                            |
| 502    | `bad_gateway`                           | Returned by the web proxy when the API is unreachable                                                                                                                        |
| 503    | `service_unavailable`                   | Outreach draft generation failed                                                                                                                                             |
| 500    | `internal_error`, `serialization_error` | Unexpected. Search the logs for the `requestId`.                                                                                                                             |

Every response carries an `x-request-id` header. Send your own `x-request-id` (up to 64 chars) to correlate calls.

## Pagination

List endpoints that can grow use **offset pagination** ([ADR-0005](/docs/decisions/0005-offset-pagination-for-leads)):

| Param      | Default                              | Max                |
| ---------- | ------------------------------------ | ------------------ |
| `page`     | 1                                    | —                  |
| `pageSize` | 6 (leads, pipeline runs), 25 (audit) | 50 (100 for audit) |

Response envelope:

```json
{ "items": [ … ], "page": 1, "pageSize": 6, "total": 42, "totalPages": 7 }
```

`totalPages` is at least 1. Leads are ordered deterministically (`score_total desc, id desc` by default), so pages
are stable while data is unchanged.

The `/platform/data/*` lists default to **25** per page (max 100) and return a `DataPage`, which adds
`totalIsEstimate` (true when an unfiltered total comes from `pg_class.reltuples` on a table above 50 000 rows) and
`nextAfter`, a keyset cursor for deep event pages
([ADR-0018](/docs/decisions/0018-hybrid-offset-keyset-pagination),
[details](/docs/platform-data/explorer-and-pagination#pagination)).

## Rate limits

Global: `RATE_LIMIT_MAX` requests per `RATE_LIMIT_WINDOW` per client (300 per minute), stored in Redis. Tighter
per-route limits: login 5 per minute (per IP + email), forgot-password 5 per minute, accept-invite and
reset-password 10 per minute, outreach draft 20 per minute.

## Conventions

- Ids are UUIDs (v7). Invalid UUIDs in paths return 400.
- Timestamps are ISO-8601 strings in UTC. Date-only filters use `YYYY-MM-DD`.
- Create endpoints return **201**, queued work **202**.
- `PATCH` bodies are partial. Omitted fields are unchanged, and `null` clears nullable fields where allowed.
