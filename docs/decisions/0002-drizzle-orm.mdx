---
title: ADR-0002 — Drizzle ORM with plain SQL migrations
description: Data access uses Drizzle ORM and drizzle-kit SQL migrations instead of Prisma.
---

**Status:** Accepted · **Date:** 2026-09-24

## Context

SelloEasy needs a typed data layer for PostgreSQL 16 that handles:

- a relational core with JSONB (score breakdowns, settings, extracted evidence), `text[]` arrays, generated
  `tsvector` columns with GIN indexes, Postgres enums and partial or conditional updates;
- analytics-style SQL for dashboards (`count(*) filter (where …)`, `date_trunc`, `DISTINCT ON`) without leaving the
  ORM;
- **reviewable migrations**, including hand-written SQL such as the append-only audit trigger;
- use from several processes (API, worker, seed, CLI scripts) run by `tsx`, without a code-generation step or a
  separate query engine binary.

## Decision

Use **Drizzle ORM** (`drizzle-orm` with `node-postgres`) and **drizzle-kit**:

- the schema is TypeScript in `packages/db/src/schema/*` (identity, knowledge, intelligence, crm, audit), with
  `casing: 'snake_case'`;
- migrations are plain SQL files in `packages/db/drizzle/`, generated by `pnpm db:generate` and applied by
  `pnpm db:migrate` (the Drizzle migrator). Custom SQL lives in its own migration
  (`0001_audit_append_only.sql`);
- raw SQL fragments (`sql```) are used freely for aggregates, and typed results flow through to the API DTOs.

## Consequences

- Queries read like SQL, and complex aggregates stay in one place with full type inference.
- No generated client and no engine binary. Works as-is under `tsx` and in slim containers.
- Migrations are ordinary SQL diffs, easy to review in pull requests.
- Smaller ecosystem than Prisma: fewer tutorials, no built-in admin UI beyond Drizzle Studio, and some relational
  conveniences (nested writes) must be written explicitly. This project writes multi-table changes as explicit
  transactions anyway, to keep audit rows in the same transaction.
- Drizzle's API is still evolving across minor versions, so the version is pinned in the lockfile and upgrades are
  deliberate.

## Alternatives considered

- **Prisma**: excellent DX and ecosystem, but a heavier runtime (query engine), weaker for raw analytical SQL, and
  generated clients complicate the no-build `tsx` runtime.
- **Kysely**: a great typed query builder, but no schema-to-migration tooling of its own.
- **Raw `pg` with hand-written SQL**: maximum control, but no type safety between schema and code.

## Revisit when

- The team needs features Drizzle lacks and would otherwise hand-roll many times, or Drizzle's migration tooling
  blocks a needed change (e.g. complex online migrations).
- Row-Level Security ([ADR-0007](/docs/decisions/0007-app-level-tenancy-before-rls)) needs connection-level
  session settings that are awkward with the current client setup.
