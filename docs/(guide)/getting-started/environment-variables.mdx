All configuration is environment-driven. There is one `.env.example` at the repository root that lists every
key the platform knows about, for local runs, AWS runtime and AWS deployment alike
([ADR-0012](/docs/decisions/0012-env-driven-drivers-for-aws-readiness)).

## How configuration is loaded

- **Single schema.** Every runtime key is declared in `packages/shared/src/env.ts` as a Zod schema
  (`runtimeEnvSchema`). Deploy-time keys (group 12) are declared in `deployEnvSchema` in the same file.
- **Single loader.** Apps read configuration only through `getConfig()` / `initConfig()` from
  `@selloeasy/core` (`packages/core/src/config.ts`). Nothing else reads `process.env` directly. The one exception
  is the web app's `/api/*` proxy route, which reads `API_INTERNAL_URL` at runtime.
- **Fail fast.** Invalid or missing values stop the process at boot with a message listing each offending key,
  for example `- SES_REGION: SES_REGION is required when MAIL_DRIVER=ses`.
- **Conditional validation.** Some keys are only required when a driver needs them (see the
  "Required when" column).
- **`.env` loading for host-side development.** When running on the host, `loadDotEnv()` walks up from the working
  directory to the workspace root and loads `.env` with `process.loadEnvFile`. Values already in the process
  environment always win, so Docker and ECS-provided values are never overridden. `.env` files are excluded
  from Docker images by `.dockerignore`.
- **Secrets Manager.** With `SECRETS_SOURCE=aws-secrets-manager`, `initConfig()` first fetches the JSON secret
  `AWS_SECRETS_ID` and merges its keys over `process.env`, then validates.
- **Automatic mock mode.** If `LLM_MODE=live` (the default) but the API key of the **selected provider**
  (`LLM_PROVIDER`) is empty, the loader switches to `LLM_MODE=mock` _before_ validation and sets an internal
  `llmAutoMocked` flag. The API and worker log a warning naming the provider, and `/api/ready` reports
  `"autoMocked": true`.

<Callout type="warn">
  Booleans accept `true`, `1`, `yes` or `on` (case-insensitive). Anything else, including an empty string, is
  `false`. Empty strings for optional keys are treated as "not set".
</Callout>

<Callout type="info">
  **Docker Compose overrides.** `docker-compose.yml` injects container-network values that win over `.env`:
  `DATABASE_URL` (host `postgres`), `REDIS_URL` (`redis://redis:6379`), `S3_ENDPOINT` (`http://minio:9000`),
  `SMTP_HOST=mailpit`, `SMTP_PORT=1025`, `API_INTERNAL_URL=http://api:4000` and `NODE_ENV=production`. It also
  provides fallbacks for `STORAGE_DRIVER`, the S3 keys, `S3_FORCE_PATH_STYLE`, both JWT secrets and `APP_ENV`.
  A host-oriented `.env` (with `localhost` URLs) therefore works for both `pnpm dev` and `docker compose up`.
</Callout>

## 1. LLM — provider switch

The LLM provider is chosen by `LLM_PROVIDER`. Only the selected provider's key and model are required; the model is
**exactly** that provider's `*_MODEL` value and no model name exists in source code
([ADR-0009](/docs/decisions/0009-openrouter-model-from-env), [ADR-0017](/docs/decisions/0017-provider-adapter-layer)).
See [LLM layer & providers](/docs/pipeline/llm-providers).

| Key                         | Default           | Required when | Description                                                                                                                                                                                                                    |
| --------------------------- | ----------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `LLM_PROVIDER`              | `openrouter`      | —             | `openrouter`, `openai` or `anthropic`. OpenRouter is the documented default in `.env.example`. Also a deploy key (group 12).                                                                                                   |
| `LLM_MODE`                  | `live`            | —             | `live` or `mock`. `mock` returns deterministic fixtures for every prompt and needs no key.                                                                                                                                     |
| `LLM_MAX_CONCURRENCY`       | `4`               | —             | Maximum concurrent LLM requests **per process** (in-process semaphore).                                                                                                                                                        |
| `LLM_TIMEOUT_MS`            | `30000`           | —             | Per-request timeout. A timed-out request is retried with backoff and then fails with HTTP 408 semantics.                                                                                                                       |
| `LLM_CACHE_TTL_SECONDS`     | `604800` (7 days) | —             | TTL of the Redis response cache keyed by provider + model + prompt version + rendered prompt.                                                                                                                                  |
| `LLM_FALLBACK_PROVIDER`     | _(empty)_         | —             | Optional failover provider (`openrouter`, `openai` or `anthropic`), used when the primary still fails after retries with a retryable or 5xx error. Must differ from `LLM_PROVIDER`, and its own key and model become required. |
| `LLM_SUPPORTS_TEMPERATURE`  | _(empty = auto)_  | —             | `true` or `false` to override the built-in capability table for models newer than it. `false` stops sending `temperature`.                                                                                                     |
| `LLM_SUPPORTS_JSON_SCHEMA`  | _(empty = auto)_  | —             | `true` or `false` to force structured output on or off (`json_schema` for OpenAI-compatible APIs, a forced tool call for Anthropic).                                                                                           |
| `LLM_PRICE_INPUT_PER_MTOK`  | _(empty)_         | —             | USD per 1M input tokens, used to compute cost for providers that do not report it (OpenAI, Anthropic). Empty = cost recorded as 0.                                                                                             |
| `LLM_PRICE_OUTPUT_PER_MTOK` | _(empty)_         | —             | USD per 1M output tokens, as above.                                                                                                                                                                                            |

### Connector secrets

`HTTP_FEED` connectors that need an auth header store only the **name** of an env var in their config. The value is
read at run time from the process environment (or the Secrets Manager JSON secret), and **only names matching
`CONNECTOR_[A-Z0-9_]{1,60}`** are readable, so a connector can never send a platform secret to an external URL. These
keys are free-form, are not part of the env schema and are not listed in `.env.example`. Add them to your own `.env`,
for example `CONNECTOR_ACME_FEED_TOKEN=...`, and restart the API and worker. See
[Connectors & ingestion](/docs/platform-data/connectors-and-ingestion#connector-secrets-connector_).

provider's** key and model must be non-empty to deploy. API keys are pushed into the Secrets Manager app secret by the
deploy script (the selected provider's key is required, others are copied when set); `LLM_PROVIDER` and the
`*_MODEL` values become plain task environment variables. `MAIL_FROM` is required, and `SES_REGION` defaults to
`ap-south-1`.

## Compose-only host ports

These are read only by `docker-compose.yml` to choose the published host port. Container ports never change.

| Key                       | Default | Service / container port         |
| ------------------------- | ------- | -------------------------------- |
| `WEB_HOST_PORT`           | `3000`  | `web` :3000                      |
| `API_HOST_PORT`           | `4000`  | `api` :4000                      |
| `POSTGRES_HOST_PORT`      | `5432`  | `postgres` :5432                 |
| `REDIS_HOST_PORT`         | `6379`  | `redis` :6379                    |
| `MINIO_HOST_PORT`         | `9000`  | `minio` API :9000                |
| `MINIO_CONSOLE_HOST_PORT` | `9001`  | `minio` console :9001            |
| `SMTP_HOST_PORT`          | `1025`  | `mailpit` SMTP :1025             |
| `MAILPIT_UI_HOST_PORT`    | `8025`  | `mailpit` UI :8025               |
| `DOCS_HOST_PORT`          | `3001`  | `docs` :3001                     |
| `ALLURE_HOST_PORT`        | `5252`  | `allure` (profile `reports`) :80 |

<Callout type="warn">
  If you change `WEB_HOST_PORT`, also set `WEB_URL` (so invite and reset links point to the right port) and
  `CORS_ORIGINS`. If you change `MINIO_HOST_PORT`, also set `S3_PUBLIC_ENDPOINT` so browsers can reach
  presigned upload URLs.
</Callout>

## Validating a file

`package.json` defines `pnpm env:check` (`tsx scripts/env-check.ts`) to validate an env file against the
schemas, including `--target aws` for group 12. The script is part of the AWS deploy-readiness work described
in [AWS deployment](/docs/operations/aws-deployment). Until it is present, the runtime validation at boot is the
authoritative check. Any misconfiguration fails the API, worker, migrate or seed process immediately with the
list of invalid keys.
